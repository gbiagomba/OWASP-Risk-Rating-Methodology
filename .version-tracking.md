## Version History

### v1.0.0 (2026-10-06)
**Type:** Initial Release (MAJOR)
**Branch:** dev
**Tag:** v1.0.0

**What this version is**

The repository held only the project scaffold: no `src/`, every template file
carrying `program_name` placeholders. This version adds the tool itself,
`riskforge`, which scores threats with the OWASP Risk Rating Methodology and
writes out the derivation, and fills out the scaffold around it.

#### Methodology core

`src/model/catalog.rs` (307 lines)
- `Group` enum (`:24`): `ThreatAgent`, `Vulnerability`, `TechnicalImpact`, `BusinessImpact`. `Group::is_likelihood` (`:36`) returns true for the first two; `is_impact` (`:41`) is its negation, so the two sides of the methodology are derived from one predicate rather than two lists that could drift.
- `Factor` struct (`:62`): `key` (snake_case, used in input files, JSON and database rows), `flag` (kebab-case CLI long flag), `name` (spreadsheet wording), `group`, `anchors`.
- `Factor::anchor(score)` (`:77`): option text for an exact score, `None` between anchors.
- `MAX_SCORE` (`:87`) = 9.
- `FACTORS` (`:90`): all 16 factors with anchored option text transcribed from the `Rating` sheet of `OWASP_Risk_Rating_Template_Example.xlsx`. Anchor counts per factor range from 3 (`motive`, `loss_of_accountability`, `non_compliance`) to 5 (`skill_level`, `size`, `loss_of_integrity`). Unanchored values in `0..=9` remain valid as interpolation, matching the spreadsheet drop-downs.
- `factor_by_key` (`:292`), `factors_in` (`:297`), `GROUPS` (`:302`).
- Module doc records the one deliberate divergence from the OWASP community wiki: `loss_of_confidentiality` anchors "Minimal critical data disclosed, extensive non-sensitive data disclosed" at 4 and "Extensive critical data disclosed" at 5, where the wiki places the equivalent rungs at 6 and 7. The template is followed because it is the artifact the manual process used.

`src/model/score.rs` (127 lines)
- `Band` enum (`:16`): `Low`, `Medium`, `High`, ordered.
- `Average` struct (`:45`): holds `sum: u32` and `count: u32` rather than a float, so the exact numerator survives into the band decision and the report.
- `Average::of` (`:57`): asserts a non-empty slice. Every call site draws from a non-empty catalog group, so empty is a programming error, not possible input.
- `Average::band` (`:80`): **the load-bearing function.** Compares integer sums, `sum < 3 * count` for LOW and `sum < 6 * count` for MEDIUM. For 8 factors this is `sum < 24` and `sum < 48`. A likelihood summing to exactly 24 therefore bands MEDIUM with no dependence on floating point representation.
- `Average::value` (`:69`) and `rounded` (`:75`): float appears only here, for display, rounded to 3 decimal places so output reads `3.375` like the spreadsheet.
- `ImpactBasis` enum (`:100`): `Overall` (default), `Technical`, `Business`.

`src/model/matrix.rs` (142 lines)
- `Profile` enum (`:10`): `Capped` (default) and `Owasp`. `Profile::levels` (`:37`) returns the severities each profile can produce, which the tests use to assert the capped ceiling.
- `Severity` enum (`:59`): `Note`, `Low`, `Medium`, `High`, `Critical`, ordered. `Severity::sarif_level` (`:79`) maps Critical and High to `error`, Medium to `warning`, Low and Note to `note`.
- `lookup(profile, likelihood, impact)` (`:96`): exhaustive `match` over all 9 cells per profile. No arithmetic and no fallthrough, so a missing cell is a compile error. Capped caps High-by-High at `High` and lifts Low-by-Low to `Low`; `owasp` returns `Critical` and `Note` at those two corners. The other 7 cells are identical between profiles.
- `grid(profile)` (`:128`): rows impact-descending, columns likelihood-ascending, used by the `matrix` subcommand and the markdown and HTML renderers.

`src/model/assessment.rs` (197 lines)
- `FactorScore` (`:10`): `factor`, `score`, `assumed`. The `assumed` flag keeps an `--allow-missing` zero distinguishable from a deliberate zero in every renderer.
- `Assessment::build` (`:37`): the trust boundary. Rejects an empty title, then rejects unknown keys before scoring anything, then range-checks each score. Scores arrive as `i64` so `10` and `-1` reach this validation and are reported against their factor rather than failing earlier as an opaque integer conversion. Missing factors collect into one `MissingFactors` error listing all of them, unless `allow_missing` is set.
- `impact_for(basis)` (`:146`): returns the basis actually applied alongside the average. Under `Business`, an all-zero business group is read as unscored and the technical average substitutes, so the returned basis can differ from the requested one and the report says which was used.
- `nearest_key` (`:172`) and `edit_distance` (`:182`): two-row Levenshtein, suggesting a catalog key within distance 3. Turns `skill_lvl` into "did you mean `skill_level`?".

#### Input

`src/input/file.rs` (115 lines)
- `RawThreat` (`:14`): `#[serde(deny_unknown_fields)]`, so `sevrity: High` in an input file is an error rather than a silently ignored line.
- `parse` (`:54`): decides the document shape against `serde_yaml_ng::Value` before deserializing, accepting a single threat mapping, a sequence, or a mapping with a `threats` sequence. Deciding the shape first rather than using an untagged enum is what keeps a malformed threat's error specific; an untagged enum would collapse it to "no variant matched".
- Errors wrap in `Error::Threat { index, .. }`, so a bad score in the second threat of a batch reports as "threat 2".
- YAML is a superset of JSON, so one parser reads both.

`src/input/interactive.rs` (82 lines)
- `prompt` (`:10`): generic over `BufRead` and `Write`, which makes the loop testable over a scripted reader without a terminal. Prints each group header once, lists the anchored options, and re-prompts on a non-numeric or out-of-range answer instead of accepting it. End of input returns `Error::InputEnded` rather than a partial rating.

`src/input/schema.rs` (100 lines)
- `schema` (`:9`): JSON Schema 2020-12 generated from `FACTORS`. Every factor is `required` with `minimum: 0` and `maximum: 9`, carries its group in `x-group` and its anchors in `x-anchors`. The description states that 0 is a real score. This is the contract a coding agent reads before producing input.

`src/cli.rs` (266 lines)
- `Cli` (`:30`), `Commands` (`:39`): `assess` (also the default when no subcommand is given), `factors`, `matrix`, `schema`.
- `AssessArgs` (`:60`): `--input`, `--title`, `--id`, `--notes`, `--location`, `--format`, `--output`, `--mkdir`, `--profile`, `--impact-basis`, `--allow-missing`, `--quiet`.
- `FactorArgs` (`:210`) with a hand-written `impl Args` (`:231`) and `impl FromArgMatches` (`:251`): the 16 per-factor flags are generated by folding over `FACTORS` in `augment_args`, each one placed under its group via `help_heading` and documented by `help_for` (`:220`), which lists the anchors. This is why `--skill-level` cannot drift from the `skill_level` factor: there is no second list to update.
- `FormatArg::expand` (`:178`): expands `all`, then sorts and dedups, so `-f all,json` requests each format once.

#### Reports

`src/report/mod.rs` (205 lines)
- `Report::new` (`:44`): computes all four averages, resolves the impact basis, performs the matrix lookup, and stamps the time. Every number a renderer prints is computed once, here.
- `Report::derivation` (`:80`): the one-line audit trail, naming both averages, both bands, the basis and the profile.
- `Report::id` (`:72`) and `slug` (`:95`): stable identifier, falling back to a slug of the title.
- `Format` enum (`:121`) with `ALL` (`:139`), `extension` (`:164`), `is_binary` (`:179`) and `render` (`:185`). `Format::render` returns `Error::NeedsOutput` for `Sqlite`, since a database file cannot be streamed to standard output.

Renderers, one module each:
- `text.rs` (120 lines): grouped factor list with option text, four averages, the matrix line, and a summary table when there is more than one threat.
- `json.rs` (77 lines): `average_value` (`:9`) and `factors_value` (`:19`) are shared with the SARIF renderer, so the two cannot disagree.
- `csv_out.rs` (64 lines): one flat row per threat, 16 factor columns plus every derived value.
- `markdown.rs` (155 lines): a paste-ready threat table first, then per-threat factors, derivation and the matrix applied. `escape` (`:153`) escapes pipes and backslashes so a title cannot break a table cell.
- `html.rs` (234 lines): self-contained, inline CSS with light and dark via `prefers-color-scheme`, no scripts and no external references. `esc` (`:232`) routes every interpolated value through `html_escape::encode_quoted_attribute`.
- `sarif.rs` (93 lines): SARIF 2.1.0. One rule per distinct identifier, one result per threat, all 16 factors and both averages in `properties`. `partialFingerprints` carries identity because a rating has no source line; `locations` appears only when `--location` was given, which SARIF permits.
- `sql.rs` (126 lines): `SCHEMA` (`:9`) is the two-table schema shared with the SQLite renderer. `quote` (`:110`) doubles single quotes and replaces control characters with a space, so no title or note can escape its literal.
- `sqlite.rs` (75 lines): `write` (`:8`) uses `rusqlite` with the `bundled` feature, so there is no system SQLite dependency and cross-compilation keeps working. All values bound as parameters; one transaction per run.

`src/main.rs` (260 lines)
- `main` (`:14`) maps `Err` to `ExitCode::FAILURE`; `report_error` (`:26`) walks the whole `source` chain, so a nested parse failure still prints the file and the threat it came from.
- `collect` (`:148`): input precedence is `--input`, then per-factor flags, then interactive. Interactive is entered only when `io::stdin().is_terminal()`, so a piped invocation with no input errors out instead of hanging.
- `emit` (`:183`): standard output for a single text format; `--output` as a file for one format and as a directory for several. `ensure_directory` (`:235`) refuses to create a missing parent without `--mkdir`.

`src/error.rs` (109 lines): one `thiserror` enum. Validation variants name the factor at fault (`ScoreOutOfRange`, `UnknownFactor` with its suggestion, `MissingFactors` listing all of them); IO and parse variants carry the path.
